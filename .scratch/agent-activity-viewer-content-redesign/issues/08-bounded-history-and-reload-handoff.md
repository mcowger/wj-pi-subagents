# 08 — 100 条历史与 reload 交接

**What to build:** 为顶层活动历史加入按代理隔离的 100 个原子条目滚动窗口，并在同规格 reload 中保留权威历史、淘汰事实和运行中工具。用户可以明确知道较老活动已被移除；即使正在回看或条目仍在运行，选择、收束和迟到回填也保持确定。

**Blocked by:** 02 — 工具活动状态机与安全兜底; 07 — 任意后代实时显示草稿.

**Status:** ready-for-agent

- [ ] 顶层 TUI 对每个代理独立保留最多 100 个可淘汰原子历史条目，不建立跨代理共享额度。
- [ ] 一条完整 assistant 消息、一次工具调用、一条 `Parent message` 和一个多行 Shell 工具活动各计为一个条目；content block 数和显示行数不参与计数。
- [ ] 历史不设置总字节上限或单条正文上限，不因正文大小截断、静默省略或优先删除 thinking；允许保留的正文保持完整。
- [ ] 超过 100 条时立即从最旧的可淘汰完整条目开始删除，不留下半条消息或半个工具活动。
- [ ] 运行中工具固定保留且不会因窗口淘汰；必要时允许缓存临时超过 100 条，工具收束后立即裁剪回限制。
- [ ] 容量策略优先于用户回看，当前显示或选中条目可以被淘汰；选中项删除后移动到时间上最近的可展开项，没有候选时清除选择，滚动位置钳制到有效范围。
- [ ] 首次发生淘汰后，在正文最顶部固定显示弱化的 `Older activity omitted`；不显示条数或字节数，不占 100 条额度，不可选择或展开。
- [ ] 淘汰提示在关闭重开和同规格 reload 后继续存在；没有发生淘汰的代理不显示该提示。
- [ ] 持久历史严格按顶层实际到达顺序追加，迟到条目不插回源端位置；工具开始/结束仍按稳定活动身份合并。
- [ ] 中间运行时继续纯 fire-and-forget，不建立历史副本、待确认 outbox、ACK、重放或重试；持久活动缺口静默跳过，不显示缺口提示、不阻塞后续活动、不改变生命周期。
- [ ] 生命周期事实不是持久活动拒绝屏障；在对应运行实例传输确认永久关闭前，合法且未重复的迟到消息或工具结束仍可写入或回填。
- [ ] 同规格 reload 保留顶层权威历史、淘汰标记和运行中工具条目，匹配的迟到工具结束仍可原地回填。
- [ ] 同规格 reload 清除所有查看器展开、选择、滚动、follow 状态和全部非权威实时草稿；重新打开详情按默认状态初始化。
- [ ] 不兼容协议或运行实例不得认领历史交接；继续沿用项目既有 protocol mismatch 与资源清理语义。
- [ ] 测试覆盖每代理隔离、99/100/101 边界、原子淘汰、运行中工具固定、临时超限和收束裁剪、提示持久性、选中项淘汰、到达序、静默缺口、迟到事实以及同规格/不兼容 reload。
- [ ] 真实 TUI 手工验收覆盖至少三层代理树、长历史、活动淘汰、运行中工具、reload、孙代理实时草稿清除和主会话隔离。
- [ ] 相关类型检查、桥接构建、定向测试和完整测试套件通过；不得通过重新引入通用原始载荷或正文字节截断来满足容量测试。
