# Spec: `/agents` 子代理活动详情内容结构重构

Status: ready-for-agent

## Problem Statement

父会话用户可以从 `/agents` 树面板进入任意子代理的活动详情，但当前详情把不同性质的内容压成同一种通用时间线结构：assistant thinking 直接占用正文，工具参数采用通用字段摘要，工具结果通常被完整缓存后再决定是否折叠，消息提交、状态查询、文件读取和命令执行也缺少各自明确的展示语义。

这导致三个用户问题。第一，重要的 assistant `text` 容易被冗长 thinking 和工具输出淹没。第二，详情缓存保存了大量用户并不需要回看的文件正文、搜索结果和命令输出，而真正需要保留的父子消息与报告又没有稳定的可展开结构。第三，多级子代理的活动历史、实时 token 草稿、工具开始/结束和生命周期事实通过不同路径到达时，当前查看器不能友好处理乱序、迟到、缺失、reload 与终态收束。

用户希望保留当前“活动流优先”的详情定位，不增加结果概览或属性卡；需要重新定义每种内容类型是否支持、保留哪些数据、如何显示、如何展开，以及哪些中间状态可以作为权威历史。

## Solution

继续使用 `/agents` 树面板中的活动详情作为只读、按时间排列的子代理观察视图。标题仍显示模板、名称与子代理生命周期状态，正文仍由 assistant 内容、工具活动和新增的父代理输入消息组成，不增加结果概览、角色卡片或消息分界线。

assistant `text` 始终以正常 Markdown 完整显示。thinking 默认折叠为 `Thinking`，展开后以弱化 Markdown 显示。工具活动改为来源可验证、按工具硬编码的语义条目：Pi 原生工具与本插件工具各自只保留用户已经选择的参数和结果事实；未知或同名覆盖工具只显示工具名与执行状态。工具从开始到结束始终是同一个活动条目，开始时立即出现，结束时原地更新。

父代理输入、`send_message`、`normal_reply` 和 `final_report` 正文完整保留并可展开。工具附属正文使用统一背景且不缩进；thinking 只用弱化文字，不使用工具正文背景。用户通过 Tab 和 Shift+Tab 选择可展开条目，通过 Enter、空格或左右方向键控制展开状态。

完整活动在产生端先归一化为允许上送的语义条目，未获准保留的参数、正文与结果不跨进程传输。中间子代理运行时只尽力转发，不保存历史或待确认队列；只有顶层 TUI 运行时按代理保存最多 1000 个原子活动条目。实时 `text`/thinking token 逐层上送，在顶层作为非权威草稿重排和展示；完整 assistant 消息仍是唯一可写入持久活动历史的正文事实。

## User Stories

1. 作为父会话用户，我想保留当前以活动时间线为主体的详情页，以便直接观察子代理过程而不是先浏览结果概览。
2. 作为父会话用户，我想从 `/agents` 树中继续打开任意层级节点的详情，以便直接子代理、孙代理及更深后代使用同一种查看方式。
3. 作为父会话用户，我想在标题中继续看到模板、代理名称和子代理生命周期状态，以便确认当前查看对象。
4. 作为父会话用户，我想让详情保持只读，以便浏览活动不会向子代理发送控制或业务消息。
5. 作为父会话用户，我想让 assistant `text` 直接完整显示，以便结论不会藏在额外的折叠操作后。
6. 作为父会话用户，我想让 `text` 使用正常 Markdown，以便标题、列表、引用、链接、行内代码和代码块保持可读。
7. 作为父会话用户，我想让很长的 `text` 仍完整显示，以便报告不会因为长度被折叠或省略。
8. 作为父会话用户，我想让流式 `text` 随 token 到达实时按 Markdown 重渲染，以便观察正在形成的回答。
9. 作为父会话用户，我不想在 `text` 前看到 `Assistant` 标签、消息容器或分隔线，以便时间线保持简洁。
10. 作为父会话用户，我想让相邻 `text` content block 分别解析 Markdown，以便前一块未闭合的语法不会破坏后一块。
11. 作为父会话用户，我想默认折叠 thinking，以便过程推理不会淹没 assistant 输出和工具状态。
12. 作为父会话用户，我想让折叠 thinking 只显示 `Thinking`，不显示行数或正文预览，以便条目紧凑稳定。
13. 作为父会话用户，我想展开 thinking 后继续看到其 `Thinking` 标题，以便随时知道折叠入口和内容性质。
14. 作为父会话用户，我想让 thinking 正文以弱化 Markdown 顶格显示，以便既可阅读又与正常 `text` 保持层级差异。
15. 作为父会话用户，我不想在 thinking 正文前看到逐行前缀、缩进或独立背景，以便 Markdown 结构不被额外装饰干扰。
16. 作为父会话用户，我想让同一消息内相邻 thinking 块合并，以便避免连续重复的 `Thinking` 标题。
17. 作为父会话用户，我想让被 `text` 隔开的 thinking 保持分离，以便原始 content block 顺序不被重排。
18. 作为父会话用户，我想让流式 thinking 默认继续折叠并显示 `streaming`，以便知道代理仍在生成推理。
19. 作为父会话用户，我想在手动展开流式 thinking 后持续看到新增内容，以便按需实时观察过程。
20. 作为父会话用户，我想在完整 thinking 到达后看到普通 `Thinking` 状态，以便流式标记及时收束。
21. 作为父会话用户，我想忽略 assistant 消息中的图片、原生工具调用块和未来未知块，以便详情只承担 `text` 与 thinking 两种消息内容。
22. 作为父会话用户，我想在某个 `text` 或 thinking 块结构无效时继续看到同一消息中的其他合法块，以便显示异常不会吞掉整条回复。
23. 作为父会话用户，我想在过滤后没有合法块时不产生空活动，以便时间线不出现无意义占位项。
24. 作为父会话用户，我想看到父代理已接纳的初始任务与后续输入，以便理解子代理行为所回应的指令。
25. 作为父会话用户，我想让所有父代理输入统一显示为 `Parent message`，以便不必区分首条任务和后续补充消息。
26. 作为父会话用户，我不想在 `Parent message` 上重复父代理名称或 ID，以便摘要保持紧凑。
27. 作为父会话用户，我想让父代理输入默认折叠并可查看完整 Markdown，以便兼顾时间线密度与上下文可追溯性。
28. 作为父会话用户，我不想在活动详情中看到 system prompt、模板正文或上下文文件正文，以便运行配置不会混入活动历史。
29. 作为父会话用户，我想在工具开始执行时立即看到一条运行中记录，以便知道子代理当前卡在哪项操作。
30. 作为父会话用户，我想让工具完成时原地更新同一个条目，以便开始和结果不会重复占两行。
31. 作为父会话用户，我想让一次工具调用始终只算一个活动条目，以便历史计数符合实际活动单元。
32. 作为父会话用户，我想让完成状态不可逆，以便迟到的开始事件不会把成功或失败工具退回运行中。
33. 作为父会话用户，我想在工具开始事件丢失但结束事件到达时仍看到完成记录，以便尽力而为的传输仍保留有用结果。
34. 作为父会话用户，我想让重复或迟到的工具事件保持幂等，以便不会产生重复条目。
35. 作为父会话用户，我想让运行中工具在代理进入 `idle` 时显示结果不可用警告，以便不会永久显示为仍在执行。
36. 作为父会话用户，我想让运行中工具在代理进入 `failed` 时收束为红色失败，以便终态和工具状态一致。
37. 作为父会话用户，我想让运行中工具在代理进入 `terminated` 时收束为中性未取得结果，以便不会伪造工具失败。
38. 作为父会话用户，我想让随后到达且身份匹配的工具结束事实回填已收束条目，以便短暂传输延迟不会留下永久错误状态。
39. 作为父会话用户，我想让 Pi 原生工具和本插件工具获得专用摘要，以便每类工具只显示真正有用的信息。
40. 作为父会话用户，我想让第三方扩展、MCP 和来源不明工具只显示工具名与状态，以便未知参数或结果不会被通用规则泄露。
41. 作为父会话用户，我想让同名覆盖的扩展工具走未知工具规则，以便它不会被误认为 Pi 原生或本插件实现。
42. 作为父会话用户，我想让专用解析忽略未来新增字段，以便 Pi 小版本升级不会无故破坏已有展示。
43. 作为父会话用户，我想让缺少必需字段或字段类型错误的专用工具降级显示，以便观察数据问题不会使代理失败。
44. 作为父会话用户，我想让普通工具摘要保持单行，以便高频活动容易扫描。
45. 作为父会话用户，我想让长路径从中间省略并保留两端，以便同时识别目录来源和文件名。
46. 作为父会话用户，我想让其他超宽摘要字段从右侧省略，以便内容不越过面板边界。
47. 作为父会话用户，我想让运行中工具使用强调色，以便快速找到正在执行的操作。
48. 作为父会话用户，我想让成功和中性工具使用弱化色，以便它们不会压过 assistant 正文。
49. 作为父会话用户，我想让警告工具使用警告色，以便区分可恢复的不完整状态。
50. 作为父会话用户，我想让真正失败的工具摘要整行红色，以便错误易于定位。
51. 作为父会话用户，我想让未知工具失败时只显示红色工具名，以便不展示未经许可的错误结果。
52. 作为父会话用户，我想让工具取消也按普通失败显示，以便第一版不引入依赖上下文的取消特例。
53. 作为父会话用户，我想让 `read` 显示路径、可选 offset、limit 和截断事实，以便知道读取范围是否完整。
54. 作为父会话用户，我不想让 `read` 保存文件正文或图片结果，以便活动历史不复制被读取内容。
55. 作为父会话用户，我想让 `write` 成功时只显示路径，不显示写入行数、UTF-8 大小或任何写入统计，以便写入规模信息不进入活动历史。
56. 作为父会话用户，我不想让 `write` 保存写入正文或原始结果，以便活动历史不复制生成文件。
57. 作为父会话用户，我想让 `write` 失败时只在摘要显示路径，以便未发生的写入不会展示成功统计。
58. 作为父会话用户，我想让 `edit` 成功时只显示路径，不显示编辑块数或任何编辑统计，以便变更规模信息不进入活动历史。
59. 作为父会话用户，我不想让 `edit` 保存 oldText、newText、diff、patch 或结果正文，以便活动历史不复制变更内容。
60. 作为父会话用户，我想让 `edit` 失败时只在摘要显示路径，以便未应用的修改不会展示成功统计。
61. 作为父会话用户，我想让 `bash` 和 `powershell` 的完整命令参数始终显示，以便多行命令的实际执行意图不会丢失。
62. 作为父会话用户，我想让 Shell 状态摘要和命令代码区分离，以便状态更新不会重排命令正文。
63. 作为父会话用户，我想让 Shell 摘要显示可选 timeout，以便理解调用约束。
64. 作为父会话用户，我不想让 Shell 工具保存或展示 stdout、stderr、退出码、超时正文或异常正文，以便大量输出不会进入活动历史。
65. 作为父会话用户，我想让 Shell 结果只表达成功或失败，以便其展示规则保持简单。
66. 作为父会话用户，我想让 `grep` 显示 pattern、路径及所有非默认 glob、ignoreCase、literal、context 和 limit，以便还原搜索条件。
67. 作为父会话用户，我想让 `grep` 显示无匹配、达到限制和截断等结果事实，以便理解搜索是否完整。
68. 作为父会话用户，我不想让 `grep` 保存匹配正文，以便源码片段不会重复进入历史。
69. 作为父会话用户，我想让 `find` 显示 pattern、搜索根和非默认 limit，以便还原文件查找范围。
70. 作为父会话用户，我想让 `find` 显示无文件、达到限制和截断等结果事实，以便理解结果是否完整。
71. 作为父会话用户，我不想让 `find` 保存命中路径列表，以便大型目录不会制造冗长活动。
72. 作为父会话用户，我想让 `ls` 显示目录和非默认 limit，以便还原目录查看范围。
73. 作为父会话用户，我想让 `ls` 显示空目录、达到限制和截断等结果事实，以便理解目录结果。
74. 作为父会话用户，我不想让 `ls` 保存目录条目，以便目录内容不会重复进入活动历史。
75. 作为父会话用户，我想让 `grep`、`find`、`ls` 未提供路径时显示 `.`，以便默认工作目录是明确事实。
76. 作为父会话用户，我想让非 Shell 的 Pi 原生工具失败时保留完整原始错误，以便需要时查看全部诊断内容。
77. 作为父会话用户，我想让 Pi 原生工具错误默认折叠，以便长错误不会占满视口。
78. 作为父会话用户，我想让展开的 Pi 原生工具错误使用红色预格式化纯文本，以便保留空白与换行且不误解析 Markdown。

84. 作为父会话用户，我想让 `send_message` 正文完整保留并默认折叠，以便可按需审计实际发送内容。

## Implementation Decisions

### 产品与领域边界

- 详情页继续是子代理活动流的只读投影，不新增结果概览、属性详情卡、控制按钮或主从分栏。
- 子代理生命周期状态继续只描述运行事实；消息提交、工具执行结果、活动缺失和实时草稿状态不得改变生命周期。
- 标题继续显示模板 ID、代理名称和当前生命周期状态。树面板已有的上下文占用、活动阶段、错误码与终止结果不会自动复制到标题或独立概览中。
- 活动详情仍只存在于 TUI overlay；内容不注入父会话消息，也不进入父模型上下文。

### 规范活动条目 seam

- 在 Pi 事件产生端与跨进程活动流之间建立一个规范活动条目 seam。该 seam 负责来源验证、字段白名单、正文保留策略、稳定身份、分块和安全净化；传输、缓存与查看器只消费规范条目，不再理解任意原始工具参数或结果。
- 规范活动条目至少覆盖 assistant 消息、父代理输入消息、工具调用和合成历史提示。assistant 消息与工具调用是原子条目；工具开始和结束是同一条目的状态事实。
- 工具规范化必须在子代理产生事件时发生。各专用规则未允许的参数、文件内容、命令输出、搜索结果、目录列表和结构化快照在该处丢弃，不得先上送再由 UI 隐藏。
- 工具来源身份属于规范化输入。只有来源确认是当前 Pi 原生实现或本插件注册实现的工具才能使用专用规则；第三方扩展、MCP、同名覆盖和来源不明工具走未知工具规则。
- 专用规则宽容接受未来新增字段并忽略它们；必需字段缺失或类型错误时降级为未知工具条目。降级是展示行为，不是协议故障或生命周期故障。
- 用户可见内容过滤 ANSI 与危险终端控制字符；这是终端安全要求，不视为正文截断。

### Assistant 内容

- 支持的 assistant content block 只有 `text` 和 thinking。图片、原生工具调用块及未知类型逐块忽略；声明为支持类型但字段无效的块也逐块忽略。过滤后为空则不创建消息条目。
- 一条完整 assistant 消息是一个原子历史条目，并保留原始合法块顺序。
- 每个 `text` 块独立作为 Markdown 文档渲染，不增加角色标签、消息边框或消息分隔线。`text` 始终完整显示，不按长度或 Markdown 类型折叠。
- 相邻 thinking 块合并为一个 thinking 组；被 `text` 隔开的 thinking 保持独立。thinking 默认折叠，摘要只显示 `Thinking`，不显示行数或内容预览。
- 展开的 thinking 保留展开标题，正文顶格显示弱化 Markdown；不缩进、不加逐行前缀、不使用工具正文背景。
- 多个 thinking 和其他可展开条目可以同时保持展开。
- 完全相同的 assistant `text`、`normal_reply` 或 `final_report` 正文不去重，每次活动都独立保留。

### 父代理输入消息

- 初始任务和后续由接收侧实际接纳的父代理消息进入接收者的活动历史。未被接纳的父消息不作为 `Parent message` 写入接收者历史；发送者侧失败的 `send_message` 尝试仍按工具活动保留。
- 所有父代理输入统一摘要为 `Parent message`，不区分首条与后续消息，也不显示父代理身份。
- 父代理输入正文完整保留、默认折叠，并以正常 Markdown、统一展开背景、顶格无缩进方式显示。
- system prompt、模板正文、上下文文件及其加载清单均不进入活动详情。

### 工具共同行为

- 工具开始时立即创建运行中条目；结束时以稳定活动身份原地更新为成功或失败。一次工具调用只形成一个原子历史条目，不显示独立开始行与结束行，也不显示执行耗时。
- 稳定工具关联至少包含产生代理身份、运行实例身份、工具活动 ID 和执行代次。重复事件幂等；完成状态不可退回运行中。
- 结束事实必须自包含该工具规则允许的摘要。开始事实丢失时，结束事实仍可创建完成条目；结束先到后，迟到开始忽略。
- 代理进入 `idle` 时，仍运行的工具收束为警告色 `result unavailable`；进入 `failed` 时收束为红色失败；进入 `terminated` 时收束为中性 `terminated before result`。随后到达且代理身份、活动 ID、执行代次匹配的结束事实可以回填真实状态。
- 普通摘要维持单行。路径采用中间省略，其他过宽字段从右侧省略。Shell 命令和展开正文是多行例外。
- 状态视觉层级为：运行中使用强调色；成功与中性结果使用弱化色；警告使用警告色；工具调用失败的摘要整行使用错误色。
- 取消不设中性特例；收到工具错误结束事实时仍按失败显示。
- 未知工具成功、运行中或失败都只显示工具名与状态；失败使用红色，不保留参数、结果或错误正文。
- 可展开工具摘要的行首顺序固定为状态图标、折叠标记、工具摘要。Shell 命令始终展开，不显示折叠标记。
- 所有工具展开正文使用同一种整行背景并顶格显示。消息正文使用正常 Markdown 文字样式；Pi 原生错误使用红色预格式化纯文本。

### Pi 原生工具规则

- `read`：摘要保留 path、可选 offset、limit，以及成功结果中的 truncated 等不完整事实；不保存文本正文、图片结果或原始成功结果。失败时仍显示相同调用参数，完整原始错误默认折叠并可展开。
- `write`：成功摘要只显示 path，不显示根据输入计算的行数、UTF-8 字节大小或任何写入统计；不保存 content 或成功结果。失败摘要也只显示 path，完整原始错误默认折叠并可展开。
- `edit`：成功摘要只显示 path，不显示 edits 数量或任何编辑统计；不保存 oldText、newText、diff、patch、首个修改行或成功结果。失败摘要也只显示 path，完整原始错误默认折叠并可展开。
- `bash` 与 `powershell`：状态摘要只显示工具名和可选 timeout；完整 command 始终在独立代码区域显示，使用统一背景且不缩进、不折叠、不截断。结束后只表达成功或失败，不保存或显示 stdout、stderr、退出码、超时正文、异常正文或其他结果文本。
- `grep`：摘要保留 pattern、path，以及全部非默认 glob、ignoreCase、literal、context、limit。未提供 path 时显示 `.`。成功结果只保留 no matches、limit reached、truncated、长行截断等结果事实；不保存匹配正文。失败仍显示全部调用参数，完整原始错误默认折叠并可展开。
- `find`：摘要保留 pattern、path 和非默认 limit；未提供 path 时显示 `.`。成功结果只保留 no files、limit reached 和 truncated 等事实；不保存路径列表。失败仍显示全部调用参数，完整原始错误默认折叠并可展开。
- `ls`：摘要保留 path 和非默认 limit；未提供 path 时显示 `.`。成功结果只保留 empty directory、limit reached 和 truncated 等事实；不保存目录条目。失败仍显示全部调用参数，完整原始错误默认折叠并可展开。
- 除 Shell 特例外，Pi 原生工具完整错误不做内容摘要或字符截断，默认折叠；展开后按面板宽度软换行，保留可读换行和空白，不解析 Markdown，并过滤终端控制序列。

### 本插件工具规则

- 本插件专用工具集合为 `get_agent_templates`、`spawn_agent`、`send_message`、`wait_agent`、`interrupt_agent`、`terminate_agent`、`get_agent_status`、`get_agent_tree`、`normal_reply`、`final_report`。
- 插件工具失败只显示规范稳定错误码，不显示底层异常正文。消息类工具的尝试正文是已允许的输入内容，失败时仍可展开。
- `get_agent_templates`：成功只显示模板数量；不保存模板 ID、描述、工具、扩展或其他配置。
- `spawn_agent`：显示 name、template ID 和成功返回 UUID 的固定前八位；不显示 depth 或初始 state。显示层不处理八位前缀碰撞，内部始终使用完整 UUID。
- `send_message`：显示目标名称和固定八位短 ID；不显示 `accepted`。完整 message 在参数完整的工具开始事实到达后即可展开，成功或失败都保留。
- `wait_agent`：单目标显示名称与短 ID，多目标显示数量；显示 outcome，批量释放时显示释放者和释放 outcome，失败终态显示安全错误码；不保存原始结构或报告正文。只要工具调用成功返回，reply、final_report、idle、timeout、正常 terminal 和 batch release 都使用成功符号；返回目标 `state: failed` 或调用本身失败时使用红色失败。
- `interrupt_agent`：显示目标和实际控制结果。进入 interrupting 为成功； unchanged 或 compaction_active 为中性；稳定调用错误为红色失败。
- `terminate_agent`：显示目标、terminated count、幂等和 forced 事实。正常回收为成功；already terminated 为中性；forced 成功为警告；termination incomplete 或调用失败为红色。
- `get_agent_status`：显示目标、生命周期状态；working/interrupting 时可显示 activity phase，failed 时显示错误码，terminated 时显示 termination result。不保存 revision、时间、上下文占用或完整快照。查询成功始终使用成功符号；目标为 failed 时只将 failed 与错误码片段标红；查询调用失败时整行红色。
- `get_agent_tree`：成功只显示工具名和成功状态；不保存 revision、scope、节点列表或统计。
- `normal_reply` 与 `final_report`：摘要只显示工具名，不显示 `accepted`。完整 message 在参数完整的开始事实到达后即可展开，成功或失败都保留；工具状态变化不自动收起正文。
- 工具参数不做 token 级流式显示。只有参数完整且 Pi 发出工具开始事实后，工具条目及其可展开输入才出现。

### 选择、展开与滚动

- Tab 按时间向后、Shift+Tab 按时间向前循环遍历全部可展开条目。Enter 与空格切换当前条目；右方向键只展开，左方向键只折叠。上下方向键继续滚动，Esc 返回树面板。
- 当前选择只通过整行选中背景表达，不增加前缀、缩进或额外文字。
- 打开详情时重置所有展开状态、滚动和选择；默认自动跟随底部，并选择当前视口中最新的可展开条目。当前视口没有可展开项时不建立虚假选择。
- 新活动不得抢占现有选择。Tab 目标位于视口外时，只滚动使其刚好可见。
- 展开保持摘要当前屏幕位置，并暂停自动跟随；折叠不会自动恢复。用户滚到底部或 Tab 循环回底部最新条目后恢复跟随。
- 多个条目可以同时展开。关闭详情再打开不保留任何展开、选择、滚动或 follow 状态。
- footer 始终为 `↑↓ scroll · Tab/Shift+Tab select · Enter expand · Esc back`；暂停时不显示额外提示。宽度不足时按既定单行截断规则处理。

### 实时显示草稿

- 实时 `text` 与 thinking token 是显示事实，不进入持久活动历史、1000 条计数或父模型上下文。完整 assistant 消息是正文历史的唯一权威来源。
- 每个子代理产生的实时 token 都逐层向顶层运行时转发；中间运行时只转发，不缓存。顶层即使没有打开对应详情，也为每个代理维护当前实时草稿。
- 实时流的逻辑身份至少包含 agent ID、runtime incarnation ID 和 stream ID；delta 与 complete 都携带该身份及严格递增 sequence。不同代理、进程重启或 stream ID 复用不得关联到同一草稿。
- 顶层只显示从 sequence 1 开始的连续前缀。未来帧可先到并按 sequence 暂存；缺失帧到达后，连续应用缺失帧和随后已缓存帧。重复和旧帧幂等忽略。
- 缺帧不设置时间超时。每个流最多缓存 256 个尚未连续的未来帧；连续前缀本身不设聚合字节上限。
- future buffer 超过 256 帧时，保留已验证连续前缀，丢弃 future buffer 并冻结该流。冻结 text 在末尾显示弱化省略号；冻结 thinking 的标题显示 `Thinking · streaming incomplete`，展开正文末尾也显示弱化省略号。
- 正常流式 thinking 的折叠标题显示 `Thinking · streaming`。手动展开后保持展开并实时增长；完整权威消息到达后变为普通 `Thinking`。
- `message_complete` 只表示实时生成收束，不是正文权威事实。若连续前缀完整，complete 后继续显示临时正文；不得把草稿写入历史。
- 权威完整消息必须携带可与实时流精确关联的身份。到达后原地替换并清除对应草稿；权威消息先到时，后续该流的迟到 delta 和 complete 忽略。
- 代理进入 idle、failed 或 terminated 时清除仍未被权威消息替换的草稿。之后同一运行实例、身份合法且未重复的迟到权威消息仍可写入历史；生命周期不是活动拒绝屏障。
- 同规格 reload 清除全部实时草稿和 viewer 交互状态，不迁移非权威 token；持久历史和运行中工具条目继续保留。

### 持久活动传输与缓存

- 只有顶层 TUI 运行时维护可回放活动历史。中间子代理运行时对自身与后代规范活动只做逐层 fire-and-forget 转发，不保留历史副本，也不建立待确认 outbox、ACK、重放或重试。
- 持久活动传输是尽力而为。中间发送失败允许顶层历史形成永久缺口；顶层静默跳过可识别缺口，不显示缺口提示、不阻塞后续活动，也不改变生命周期。
- 大正文可按传输帧约束分块，但只有同一条目所有分块完整收齐、身份和顺序验证通过后才能原子写入历史。缺块不得产生部分权威正文。
- 持久历史按顶层实际到达顺序追加，迟到消息不会插回源端时间位置或重排已显示条目。工具开始与结束仍按稳定活动身份合并。
- 每个代理最多保留 1000 个原子历史条目，不设总字节、单条正文或连续实时前缀的聚合字节上限。
- 一个完整 assistant 消息、一个工具调用、一条父代理输入、一个多行 Shell 工具条目各计为一个条目；显示行数和 content block 数不参与额度计算。
- 超过 1000 条时立即从最旧的可淘汰完整条目开始删除。运行中的工具固定保留，必要时允许暂时超过 1000 条；工具全部收束后立即恢复限制。
- 容量限制优先于用户回看。正在显示或选中的旧条目可以被淘汰；选择移到时间上最近的可展开条目，滚动位置钳制到仍存在的内容范围。
- 一旦发生过历史淘汰，在正文最顶部固定显示弱化的 `Older activity omitted`。该提示不显示条数或字节数，不占 1000 条额度，不可选择或展开，并在重新打开详情与同规格 reload 后保留。
- 同规格 reload 保留顶层持久历史、淘汰标记和运行中工具条目。reload 期间到达且稳定身份匹配的工具结束事实仍可回填。
- 对应运行实例的传输确认永久关闭后拒绝新的活动事实；关闭前到达的同实例迟到事实仍按身份、幂等与到达序规则处理。

### 明确接受的风险

- 历史只限制条目数量，不限制字节数。1000 条长 Markdown、父子消息或错误正文可能占用大量内存；这是正文完整性优先的明确产品取舍。
- 连续实时草稿不设总字节上限，只限制乱序 future buffer 的帧数；单个长时间生成中的草稿也可能持续增长。
- 中间运行时没有 outbox 或重传，持久活动和实时 token 都可能因转发失败缺失。持久缺口静默，实时内容最终以权威完整消息为准。
- 固定八位短 UUID 可能发生显示碰撞；内部关联不使用短 ID，因此碰撞只影响显示辨识度。

## Testing Decisions

- **好测试的标准**：只断言用户可观察的规范条目、渲染表面、公开交互状态、缓存回放和跨运行时交付结果；不绑定私有集合、辅助函数、条件分支顺序或具体定时器实现。测试名称使用活动流、子代理生命周期状态、消息发送和工具活动等项目领域语言。
- **主要测试 seam**：继续使用现有活动查看器投影模型作为最高层 UI seam。向其提供规范历史条目、实时显示事实、生命周期更新和键盘序列，断言最终语义行、主题样式、选择、展开、滚动与 follow 状态。overlay 绑定只验证必要的宿主接线，不在薄壳重复内容矩阵。
- **规范化 seam**：通过产生端的规范活动条目接口测试来源识别和字段白名单。对每个 Pi 原生工具、本插件工具、同名覆盖工具和未知工具分别断言允许字段存在、禁用字段在跨进程前已经消失，而不是只断言 UI 没显示。
- **协议 seam**：通过现有桥接/监督通道 codec 的公开收发结果测试稳定身份、分块原子提交、sequence、重复、乱序、未来帧缓存、冻结、complete 和权威消息关联。使用可控事件序列，不使用真实延时证明顺序行为。
- **运行时 seam**：通过现有控制器与运行时装配的高层测试建立根、子代理、孙代理和更深树，验证中间层只转发、顶层才缓存、没有 outbox、失败可形成静默缺口、实时 token 可逐层到顶层，以及不同代理和运行实例不会串流。
- **缓存 seam**：测试每代理 1000 个原子条目、原子淘汰、运行中工具固定、临时超限与收束后裁剪、`Older activity omitted`、选中项淘汰和同规格 reload 保留。测试不根据显示行数或正文大小推断条目数。
- **assistant 渲染矩阵**：覆盖独立 Markdown text block、长正文不折叠、相邻 thinking 合并、被 text 分隔的 thinking、thinking 默认折叠与多项展开、无行数标题、弱化 Markdown、无缩进/前缀/背景、不支持与无效块逐块忽略。
- **父消息矩阵**：覆盖初始任务、后续已接纳消息、未接纳消息、统一 `Parent message` 摘要、完整 Markdown 展开，以及 system/template/context 内容不进入历史。
- **Pi 工具矩阵**：逐个覆盖 `read`、`write`、`edit`、`bash`、`powershell`、`grep`、`find`、`ls` 的运行中、成功、失败、自包含结束和禁用正文。尤其断言文件内容、写入 content、diff/patch、shell 输出、匹配正文、路径列表和目录条目不会越过规范化 seam。
- **插件工具矩阵**：逐个覆盖模板计数、spawn 短 ID、消息正文与失败保留、wait 各 outcome、interrupt 中性阻塞、terminate forced/幂等/不完整、status 局部错误样式、tree 极简结果、normal reply 和 final report 展开，以及所有稳定错误码投影。
- **工具状态矩阵**：覆盖开始后立即可见、结束原地更新、重复幂等、结束先到、开始缺失、完成后迟到开始、idle/failed/terminated 收束和匹配结束回填。工具状态不得倒退。
- **实时草稿矩阵**：覆盖 9 先于 8、多个连续未来帧、重复/旧帧、无超时等待、256 帧边界、超限冻结、text 省略号、thinking incomplete 标题、complete 后保持、权威消息前后两种到达顺序、生命周期清理和查看器关闭期间组装。
- **交互矩阵**：覆盖初始选择当前视口最新可展开项、Tab/Shift+Tab 全历史循环、视口外最小滚动、新事件不抢选择、选中背景、Enter/Space/左右键、多项同时展开、展开暂停 follow、恢复 follow、固定 footer、关闭重开重置。
- **安全与宽度**：覆盖 ANSI/方向控制清理、Markdown 与预格式化错误差异、统一展开背景、红色失败、局部红色状态、路径中间省略、其他摘要右侧省略、Unicode 显示宽度和窄终端不溢出。
- **既有测试先例**：复用现有活动查看器纯模型测试、代理树 overlay fake UI 测试、桥接事件规范化测试、活动通道与控制器多层汇聚测试、runtime reload handoff 测试和主题 marker 测试；只在现有 seam 无法表达规范活动条目时新增一个产生端规范化接口。
- **手工验收**：在真实 Pi TUI 中创建至少三层代理树，打开直接子和孙代理详情，观察 Markdown、thinking、父消息、Pi 工具、插件工具、流式乱序恢复、Tab 选择、多项展开、终态收束与 reload。确认主会话没有新增详情内容，未知工具不泄露参数，Shell 不显示输出。
- **完成门槛**：相关类型检查、桥接构建、定向测试和完整测试套件全部通过；原有 `/agents` 树交互、生命周期投影、父子消息接纳和资源控制行为无回归；不得通过扩大通用字段展示、保留原始工具载荷或放宽安全断言来使测试转绿。

## Out of Scope

- 将详情页改造成结果概览、属性卡、仪表盘或父子消息聊天界面。
- 在详情中新增 steer、interrupt、terminate、send 或其他写操作控件。
- 支持 assistant 图片、原生 toolCall content block 或未来未知消息块的可视化。
- 展示 system prompt、模板正文、上下文文件正文或加载清单。
- 为第三方扩展、MCP 或用户自定义工具提供配置化、插件化或工具自描述渲染规则。
- 项目级工具显示配置；本次专用规则全部硬编码。
- 工具参数 token 级流式展示。
- 保存 `read` 结果、写入正文、edit diff、Shell 输出、grep 匹配、find 路径列表、ls 目录条目或完整 agent tree/status 快照。
- 工具执行耗时、运行中计时器或完成时间展示。
- 动态短 UUID 唯一前缀或短 ID 碰撞提示。
- 持久活动传输的 ACK、重传、outbox、应用 FIFO 或缺口告警。
- 按源端序号重排已经写入的持久历史。
- 历史或实时草稿的总字节上限、单条正文上限、磁盘落盘或跨 Pi 进程重启持久化。
- 在不同代理之间共享一个全局 1000 条额度。
- 非 TUI 模式的活动详情展示。
- 修改常驻 Agents widget、`/agents` 树面板的节点字段、排序、折叠或生命周期颜色。

## Further Notes

- 本规格是现有子代理活动查看器的后续重构规格。发生冲突时，本规格覆盖旧规格中“通用工具参数/结果渲染、长工具结果全文缓存、thinking 逐行直接显示、paused footer、每层祖先缓存、16 KiB 聚合正文限制、缺序即清空草稿”等决定；旧规格的 `/agents` 入口、只读 overlay、活动流优先、任意后代可查看、父模型上下文隔离和非 TUI no-op 仍然有效。
- `text`、thinking、父代理消息和工具活动属于活动流；它们不等于会话事件。`normal_reply` 和 `final_report` 的工具记录只说明子代理尝试或成功提交相应消息，仍不改变子代理生命周期状态，也不自动结束 Pi 回合或会话。
- `wait_agent` 中的 timeout、idle、terminal 是工具成功返回的数据，不自动表示工具失败。目标 `state: failed` 与查询/等待调用本身失败必须在视觉和测试中保持区分。
- 实现需要为实时消息和工具调用引入不会跨代理或运行实例冲突的关联身份。显示用八位短 UUID 不能承担协议身份、去重或回填职责。
- 只按 1000 个原子条目限制历史意味着没有可证明的内存硬上限。实现和评审不得在未修改本规格的情况下重新引入静默字节截断或正文省略。
- 本次只发布该 `spec.md`，不创建 implementation issue，不修改生产代码，也不执行实现测试。
