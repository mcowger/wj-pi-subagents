# Spec: 子代理实时活动查看器（agent activity viewer）

Status: ready-for-agent

## Problem Statement

父会话的用户在派发子代理后，只能看到每个子代理的生命周期状态与粗粒度活动阶段（processing / executing_tools / compacting），看不到它实际在做什么：读了哪些文件、执行了什么命令、产出了什么中间输出。用户要么盲等到最终报告（final_report）到达，要么失去对子代理工作的信任感与可调试性。过程信息对父模型不可见是有意的设计（上下文经济性），但对用户也不可见则是纯粹的展示缺口。

## Solution

在现有 `/agents` 树面板中选中任意节点并回车，进入该子代理的"实时活动查看器"：一个独立的全屏 overlay，以接近根会话 TUI 的会话视图（Markdown 消息、工具调用行、可折叠的超长工具结果、自动跟随滚动）展示该子代理的全量活动流。打开即回放该子代理从启动到现在的全部历史，随后实时追加新事件。Esc 返回面板，可另选节点继续查看。

过程数据只进入查看器显示层，绝不写入父会话对话流，也绝不进入父模型上下文。查看器第一版纯只读。

## User Stories

1. 作为父会话用户，我想在 `/agents` 面板中选中任一子代理并回车，进入它的活动查看器，以便按需查看它正在做什么。
2. 作为父会话用户，我想在查看器中看到子代理的全量活动流（assistant 消息、工具调用、工具结果），以便完整了解其工作内容。
3. 作为父会话用户，我想在打开查看器时先回放该子代理的全部历史活动，以便不错过打开之前已发生的事。
4. 作为父会话用户，我想让查看器实时追加新产生的事件，以便持续跟踪进展而无需反复开关。
5. 作为父会话用户，我想让查看器以接近根会话 TUI 的方式渲染内容（Markdown、工具调用行），以便零学习成本地阅读。
6. 作为父会话用户，我想让超长的工具结果默认折叠、可展开，以便既不丢失细节也不被单条输出淹没。
7. 作为父会话用户，我想让查看器自动滚动跟随最新事件、向上滚动时暂停跟随，以便兼顾实时追踪与历史回看。
8. 作为父会话用户，我想查看树上任意层级的后代子代理（孙代理及更深），以便整棵树的每个节点对我都透明。
9. 作为父会话用户，我想用 Esc 从查看器返回树面板，以便快速切换查看对象。
10. 作为父会话用户，我想让查看器为每个子代理独立缓存、并行运行时互不串流，以便确认看到的内容属于当前查看的节点。
11. 作为父会话用户，我想让查看器内容只出现在 overlay 中而不进入主会话对话流，以便主会话保持干净、不打断当前任务阅读。
12. 作为父会话用户，我想让查看器内容不进入父模型上下文，以便不消耗父代理 token、不干扰任务执行。
13. 作为父会话用户，我想在查看器标题看到正在查看的子代理身份（模板、名称）与其生命周期状态，以便确认"我在看谁、它现在什么状态"。
14. 作为父会话用户，我想在子代理终止后仍能在本次会话内回放其活动，以便事后审计它的完整工作过程。
15. 作为父会话用户，我想让查看器保持只读，以便浏览时不会误触发对子代理的干预。
16. 作为父会话用户，我想在查看的子代理无任何已缓存活动时看到明确的空态提示，而不是空白屏幕，以便理解"没有内容"与"界面坏了"的区别。
17. 作为父会话用户，我想在流式产生的事件以合理频率出现在查看器中（而非逐字刷屏或明显滞后），以便实时感与可读性兼顾。
18. 作为扩展维护者，我想让活动事件的校验沿用桥接事件闭集的既有语义（未知事件忽略、结构违约拒绝），以便新数据面与现有安全边界一致。
19. 作为扩展维护者，我想让活动缓存只存在于父进程内存、不落盘，以便避免敏感内容（文件内容、命令输出）残留，并接受重启后历史丢失。
20. 作为扩展维护者，我想让活动流上行与现有监督消息（reply、活动阶段、控制消息）互不阻塞、互不耦合，以便新功能对现有行为零回归。
21. 作为扩展维护者，我想让每层运行时只负责收集本进程会话事件并汇聚直接子代理上行的子树流，以便孙代理透明性无需新的跨进程通道。
22. 作为扩展维护者，我想让 UI 事实净化惯例同样适用于查看器渲染的标题与摘要文本，以便阻断终端控制字符注入。
23. 作为父会话用户，我想在非 TUI 模式下完全不触发查看器相关逻辑，以便 RPC/print 场景不受任何影响。

## Implementation Decisions

### 数据面

- **桥接事件闭集加宽**：在现有安全闭集基础上新增两类事件——携带正文的消息事件（assistant 文本与 thinking 块）、带参数与结果摘要的工具执行事件。校验沿用现有规范化语义：未知事件忽略；已知事件结构违约返回 invalid 并由桥接进程关闭传输；正文设置字节上限，超限按既有 reply_too_large 惯例拒绝该事件而非中断会话。
- **监督通道活动流事件**：上行通道新增活动流事件类型，承载加宽后的子代理会话事件。它遵循现有会话事件提交语义：每次提交独立、不承诺跨事件顺序、不建立确认或屏障；查看器按到达序渲染与回放。
- **递归汇聚**：每层 pi 进程中的扩展实例将其本进程会话事件沿监督通道上行给直接父代理；每层缓存汇聚"自身事件 + 直接子代理上行的整棵子树流"。由此根端缓存天然覆盖全树，无需新增跨进程通道。
- **活动流缓存**：父端新增一个纯内存缓存模块（本特性唯一的新数据 seam）。接口风格对齐现有树快照来源：按 agent_id 追加事件、按 agent_id 读取全量（供回放）、变更通知 + 修订号（供实时追加与重绘）。无上限累积、按 agent_id 分组隔离、仅父进程生命周期内有效、不落盘。

### UI 面

- **树面板进入语义**：树面板交互投影（本仓库既有的纯投影模型）的键盘输入增加"回车"语义：对选中节点返回"进入查看"结果；overlay 装配层把该结果连同选中 agent_id 交回运行时层，由运行时层打开查看器。
- **查看器投影模型**（本特性唯一的新 UI seam）：纯类，完全参照树面板投影模型的模式——输入事件数组（回放）与追加通知；输出 `render(width)` 语义行、键盘输入处理（滚动、折叠展开、Esc）、公开状态。custom overlay 装配层为薄壳，照现有面板的绑定模式。
- **渲染语义**：类会话视图——assistant 文本按 Markdown 渲染、工具调用渲染为单行摘要（名称 + 关键参数）、超长工具结果默认折叠可展开、自动跟随最新事件、上滚即暂停跟随、底部有"已暂停跟随"提示、Esc 关闭返回面板。观感目标为"接近根会话 TUI"，接受自绘实现而非宿主渲染器复用。
- **流式节流**：逐 token 的流式更新在显示层节流合并，缓存以完整消息/完整工具结果粒度落账，兼顾实时感与内存可控。
- **只读边界**：查看器不提供 steer、停止或其他干预能力。
- **平台边界**：仅 TUI 模式；非 TUI 模式下绑定层静默 no-op，与现有面板行为一致。
- **安全边界**：查看器内容永不写入父会话消息或父模型上下文；标题与摘要文本沿用现有 UI 事实净化惯例（剥离终端控制字符）。

### 与既有共识的关系

- 常驻 widget 保持现状（不增强）。
- 入口仅 `/agents` 命令，不新增快捷键。
- 接受自绘观感与"接近根会话"的还原度上限。
- 接受无上限内存累积与父进程重启后历史丢失，放弃过程工件落盘。

## Testing Decisions

- **好测试的标准**：只测外部行为——给定输入事件/键盘序列，断言渲染输出行、公开状态或返回值；不测内部数据结构或调用关系。被测单元均为无 IO 的纯模型/纯函数，直接实例化。
- **被测模块与对应先例**：
  - 桥接事件闭集加宽：事件校验矩阵（合法/未知忽略/违约/超限）——先例：现有桥接事件规范化测试。
  - 活动流缓存：追加、回放读取、变更通知与修订号、按 agent 隔离、未知 agent 的行为、终止后仍可回放——先例：树控制器的纯模型测试。
  - 树面板回车语义：选中节点回车返回进入结果、无选中/异常态下的忽略行为——先例：现有树面板投影测试。
  - 查看器投影模型：回放渲染、实时追加渲染、滚动与跟随暂停、折叠展开、Esc 关闭、空态——先例：现有树面板投影测试（含渲染表面纯函数）。
- **不自动化**：custom overlay 装配薄壳（键盘事件到模型的接线、theme 应用）不做自动化测试，由 TUI 手工验收清单覆盖。

## Out of Scope

- 查看器内的 steer 插话与停止/中止等干预能力（列为后续迭代候选）。
- 活动事件落盘、工件留痕、跨会话/重启后回放。
- 非 TUI（RPC / print / headless）模式的任何活动展示。
- 常驻 widget 的内容增强。
- `/agents` 之外的快捷键入口。
- 像素级复用根会话渲染器，或等待宿主提供原生会话视图复用 API。
- 根会话（root）自身的活动查看；树级聚合视图或多代理同屏。

## Further Notes

- **调研依据**：pi 生态内 nicobailon/pi-subagents 与 tintinweb/pi-subagents、以及 Claude Code agent view 三方独立收敛于"常驻状态小部件 + 按需实时查看器，过程数据只进显示层"的形态；pi 官方 subagent 示例已端到端演示实时流式展示（JSONL 事件解析 + 流式更新管道）；Codex 隐藏多代理提示词引发社区信任危机，反证过程可见性是硬需求。pi 宿主无跨会话事件 API，但本仓库已建 RPC 桥，现有"只能看到状态"是协议收窄叠加的结果，非宿主能力缺口。
- **内存代价（明确接受）**：全量流含工具结果全文，长任务下缓存可能增长到数百 MB；本 spec 明确接受该代价以换取回放完整性，并以此换取实现最简（无落盘、无清理任务）。
- **术语缺口（供 /domain-modeling 处理）**：本 spec 引入了"活动流（activity stream）""活动流缓存""实时活动查看器"三个新概念，尚未进入 CONTEXT.md 术语表；建议后续用 /domain-modeling 正式收编，并与既有"活动阶段（activity phase）"概念明确区分——活动阶段是投放到树快照的粗粒度相位，活动流是供查看器消费的全量过程事件。
