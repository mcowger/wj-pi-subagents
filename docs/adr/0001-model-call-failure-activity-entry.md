# 模型调用失败作为独立活动条目，按失败尝试逐条登记

子代理调用模型失败时，错误事实只存在于收尾 assistant 消息的收尾原因与错误文本上；而既有活动条目模型（消息正文只有文本与思考两类块，正文为空的收尾消息在桥接层直接丢弃）没有任何位置能承载它，面板因此完全不显示任何模型错误。我们决定：在桥接层采集收尾原因与错误文本，新增第四种活动条目种类承载该事实，并**按每次失败尝试逐条登记**——不判定"最终失败"、不撤回、不合并、不挂到消息条目上、不复用工具失败语义；该事实属于活动事实，不驱动生命周期状态。

## Considered Options

- **把错误塞进消息条目的正文闭集**：会污染"消息正文 = 文本/思考"这条既有语义，且失败消息正文为空时仍需破坏"空正文即丢弃"的规则。
- **复用工具失败的 errorText/errorCode 语义**：工具失败是工具执行的运行事实，与模型请求失败不是同一概念，混装后无法在面板上区分"工具坏了"和"模型调不通"。
- **延迟到 Pi 回合收束时只登记最终失败**：要么先出条目再撤回，要么延迟发布；前者与"不以一个事件删除、覆盖或重排另一个事件"（会话事件提交）直接冲突。
- **采集 auto_retry_\* 以显示"第几次尝试"**：需要把尝试级事件加入桥接闭集，等于为本功能扩第二次契约。

## Consequences

- 被重试救回的失败尝试同样留在面板上；重试耗尽时会连续出现多条近乎相同的错误行。
- 父代理每次 `interrupt_agent` 都会在子代理面板留下一条"已中止"条目（与错误条目同形同标签）。
- 属不兼容契约变化：规范活动契约与监督协议版本随之递增，不提供兼容层，旧版本条目按协议故障处理。
